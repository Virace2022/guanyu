# 开发说明

观鱼的工程标识为 `guanyu`，技术栈为 Vite、vite-plugin-monkey、TypeScript 和 Svelte 5。用户使用入口见 [README](../README.md)，功能契约见 [FEATURES](FEATURES.md)，模块与接口适配见 [ARCHITECTURE](ARCHITECTURE.md)。

## 本地构建

Node.js 版本需满足 `package.json`：`^20.19.0 || ^22.12.0 || >=24.0.0`。

在仓库根目录执行：

```powershell
npm ci
npm run build
```

完整脚本为 `dist/douyu.guanyu.user.js`，更新元数据为 `dist/douyu.guanyu.meta.js`；构建同时生成精简 npm 压缩包与 `SHA256SUMS`。通过用户脚本管理器导入完整脚本；管理器不支持文件导入时，可新建脚本，将完整产物粘贴进去并保存。启用后重新打开斗鱼直播间。

生产元数据使用 npm 包 `guanyu-douyu` 在 jsDelivr 的更新和下载入口，远程更新受 CDN 缓存与管理器检查周期影响。开发服务使用独立安装项，具体地址与发布流程见[发布说明](RELEASING.md)。

## 开发调试

```powershell
npm run dev
```

服务固定在 `http://127.0.0.1:5173`，端口被占用时直接报错，不自动打开浏览器。通过用户脚本管理器安装服务提供的“开发 · 观鱼”，并保持服务运行；它支持热更新，不递增生产版本。开发项与生产项为独立安装项，在同一页面调试时只启用其中一个。

运行范围由 `vite.config.ts` 的用户脚本元数据定义：主站以数字开头的房间路径、`/beta/*`、`/topic/*` 和粉丝牌列表页，仅顶层页面，`document-idle` 执行。GM 跨源权限限定 `douyu.com` 与 `douyucdn.cn`。

## 控制台功能日志

打开浏览器开发者工具的 Console，筛选 `观鱼`，并保留 Info 与 Error 级别。脚本加载时输出小鱼字符画和版本，随后按 `[观鱼][分类][功能][阶段]` 记录实际运行结果。日志跟随功能挂载、服务发现、接口响应和手动操作产生，延迟加载不要求在启动时完成。

| 状态 | 含义 |
| --- | --- |
| 已开启 / 已关闭 | 配置或可撤回预览的开关变化，不代表功能已经生效 |
| 已就绪 / 已生效 | 已发现对应能力，或已完成日志中说明的实际操作 |
| 等待中 / 待触发、不适用 | 等待登录、任务调度、手动打开面板、开播或其他适用条件 |
| 未匹配 | 当前没有匹配目标；日志列出选择器、宿主关系或服务特征，继续按原逻辑观察 |
| 执行失败 | 已尝试的操作、依赖加载或接口请求失败，保留具体原因 |

例如：`[观鱼][播放][自动最高画质][适配] 未匹配：未找到带 onMultirateChange / props.multirates 的原生画质组件`。广告、PK、背包面板等暂未出现时，未匹配本身不证明官方改版。功能随后成功匹配或执行时会继续输出新状态。同一功能同一阶段的相同结果去重，不新增日志轮询、超时、请求或重试，也不持久保存或上传日志。排错时保留从加载到问题出现的相关日志；不要附带 Cookie、令牌或完整接口响应。

## 检查命令

| 命令 | 检查范围 |
| --- | --- |
| `npm run check` | Svelte、TypeScript、Vite 配置与构建脚本 |
| `npm run test:sign` | 鱼吧、客户端连签与补签、星推荐红包领取、共享调度、粉丝家园与任务中心契约 |
| `npm run test:settings` | 设置预览、保存、放弃恢复与预览人数确认边界 |
| `npm run test:backpack` | 续牌数量、逐房赠送状态与账号切换隔离 |
| `npm run test:playback` | 官方整改通知的原因与扣分解析，不将缺失信息或时长作为扣分 |
| `npm run test:release` | 日期版本、公历校验、北京时间日界线与 tag 一致性 |
| `npm run build` | 类型检查、生产打包、元数据一致性、语法、许可及实际 npm 包清单 |
| `npm run version:next` | 按北京时间准备下一版并写入 `version.json` |
| `npm run release:check` | 在发布工作流中核对 tag 与版本文件 |

源码或依赖改动运行 `npm run check`；构建配置、入口、权限和分发改动运行 `npm run build`。根据受影响的功能运行对应契约检查。文档与截图修改核对内容、链接和图像即可。

真实页面适配只使用内置浏览器中的斗鱼页面，可直接注入构建产物；播放器相关交互在网页全屏下验收。直接注入不能替代用户脚本管理器安装、GM 跨源桥接和开发 HMR 的独立验收。类型、接口契约、真实 DOM、实际播放与人工听感分别记录证据，具体交互清单见 [UI 规范](UI.md#交互验收)。

## 版本与产物

生产版本保存在 `version.json`，格式为 `YYYY.<月×100+日>.N`：例如 `2026.1108.3` 表示 2026 年 11 月 8 日第 3 版，1 月 8 日使用 `108`，不保留前导零。该格式同时用于 npm、用户脚本和 GitHub tag。准备新版本时执行 `npm run version:next`；北京时间同日递增序号，跨日从 1 开始，日期不能倒退。普通构建始终使用已保存版本，不写回版本文件。

`dist/npm/` 是 npm 发布包的生成目录，只有完整脚本、元数据、精简 README、LICENSE 和发布清单，不含工程依赖、截图、源码或历史版本。根 `package.json` 保持 `private: true` 和开发工程版本，生产包的版本来自 `version.json`。这些构建产物均不提交到 Git。

生产脚本使用 Oxc 压缩代码，再由 esbuild 缩短变量名、压缩空白并在约 200 字节处换行；长字符串使用合法续行，元数据头保持原样。保留必要许可，不启用属性重命名、unsafe 压缩或 eval 解包。小鱼源文件为 `assets/brand/guanyu.svg`：页面继续内联，管理器图标通过 jsDelivr 按发布 tag 读取仓库文件。仓库文档、截图和历史设计稿不进入运行包。
